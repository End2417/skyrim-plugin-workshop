# Skyrim ESP Editor v1.6.0

This release adds **Merge plugins**: combine several plugins into one new plugin, with every FormID renumbered and the changes that different mods make to the same record kept together, for Skyrim Legendary Edition plugins on Android.

**Back up your plugins before editing or merging them.**

## What’s new

- **Merge plugins.** A new **Merge** button in the toolbar, and on the start screen, combines several plugins into one new `.esp`. No plugin has to be open: pick the ones to merge and put them in load order (the last one wins where plugins disagree). If a plugin is open, it starts in the list with its unsaved edits, and you can take it out.
- **Pick several plugins at once.** **Add plugins…** takes any number of files in one go. If you have given the app access to your Skyrim folder, **Choose from the Skyrim folder…** shows a filterable checklist of every plugin in it: tick the ones you want and add them together. Plugins are put after the plugins they need, and you can move them with the arrows or press **Sort by what needs what**.
- **A preview before anything is written.** **Preview the merge** shows what will go in: how many records are new and how many change a master’s record, the masters of the new plugin, each plugin’s record types, every record with its old and new FormID (searchable, and filtered by plugin or by what happens to it), and warnings. The plugins you add are never changed. Nothing is saved until you press **Merge** and then **Save**.
- **Records are renumbered for you.** The new plugin gets one list of masters (the masters of all the plugins, vanilla ones in the game’s order, without the plugins being merged). A record keeps its ID when no other plugin uses it and gets the next free one when another does. References are updated everywhere the editor can read them: typed fields, script properties (including quest aliases), the labels of cell, world and topic groups, record headers and the overridden-forms list of a master’s header. A plugin that needs another plugin of the merge has its references to it pointed at the merged records. Records that need no change keep their exact bytes.
- **Changes to the same record are combined.** If one mod gives an NPC a sword and another gives the same NPC armor, the merged NPC gets both. Each copy of a record is compared with the original, and every change that does not collide is kept: changes in different places, items both mods add (both are kept), the fields of one struct (so one mod setting “Essential” and another changing the level give both), flags bit by bit, and entries in lists such as keywords. Counts that go with a list, such as the item count, are corrected. Only when two mods change the very same field to different values is there a collision: the later plugin’s value is used, the preview names the field, and you can tap another plugin to use its value instead.
- **Originals are read for you.** To tell what a mod changed in a record from the game, the original is needed. When you have given the app access to your Skyrim folder, `Skyrim.esm`, `Update.esm` and any other game plugin the merged plugins list as a master are read from there by themselves, only when plugins change the same record differently, and kept while the dialog is open so a new preview does not read them again. Without the folder, **Add originals yourself…** takes any plugin, and records that one of the merged plugins makes itself need no original. Without an original, one whole version of a shared record is kept, and the preview says which file to add. The original plugins are only read: nothing from them is copied into the merged plugin.
- **The result is checked.** After building, the app reads the merged plugin back, runs the same check as Check plugin, and checks that no FormID is used twice. The report is shown before you save, with the number of references renumbered, the number of script references among them, and a list of anything that could not be read.
- **Options.** Flag the result as a master (ESM; this happens by itself when every plugin is one), switch combining off to keep one whole version of each shared record, and switch off the renumbering of values in fields the editor has no layout for.

## Changes

- **Merge sits in the toolbar** next to Open, To LE, Extract and Save, and is available before a file is opened.
- **Script data reading** now reports where each script property’s FormID sits, so a merge can renumber it. Reading scripts for the report is unchanged.

## Known issues

- Navigation is not merged properly. The navigation index (NAVI) is left out, and references inside navigation meshes (NAVM) are not renumbered. Regenerate navigation for the merged plugin in the Creation Kit or xEdit before relying on it.
- A record’s script list (VMAD) is one block, so two mods that both change the scripts of one record collide. The later mod’s scripts are used. The scripts themselves (`.pex` files), SKSE plugins, meshes, textures and archives are not part of a plugin and are not merged: they still have to be installed.
- In fields the editor has no layout for, only values that clearly point at a record the plugin made itself are renumbered, and only at four-byte boundaries. Those fields are compared as a whole when two mods change them differently. References to masters inside such fields cannot be checked when a master’s position in the list changes.
- Plugins that need one of the merged plugins as a master have to be merged too or patched. The merged plugin replaces the originals, so disable them.
- Localized plugins, and plugins of different editions (Legendary Edition mixed with Special Edition), are refused. Convert them first.
- Merged plugins keep the cell blocks of the original FormIDs, so a cell that had to be renumbered can sit in a block that does not match its new FormID. The game does not use those blocks to find cells.
- Records that are too large to compare keep one whole version.
- Reading `Skyrim.esm` for a merge takes a while on a phone the first time. It is kept only while the Merge dialog is open, so opening the dialog again reads it again, and nothing readable of it is stored between sessions.
- Merge has been tested on generated plugins, including random ones that check every reference still points at the same record, and has not yet been checked against a large set of real mods. Try a small pair of mods you can verify first.
- Nothing here has been tested in the game. Test merged plugins in xEdit or in the game before relying on them.
- All other known issues are unchanged from v1.5.0.

## Upgrade notes

- Install this APK over v1.5.0. Do not uninstall first if you want to keep your settings and remembered masters.
- Your plugins are not changed by this update. Merging only reads the plugins you add, and a merged plugin is written only when you press **Save**. Saving never overwrites a file (a number is added to the name instead).
- To let the app read `Skyrim.esm` by itself when mods change the same record, set up your Skyrim folder from the info button (**Set up Skyrim files**) if you skipped it.
